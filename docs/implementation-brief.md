# 2-Tap HIIT 実装ブリーフ

MVP（最初のリリース）で「何を作るか」「どこまで作るか」をまとめた仕様書です。

---

## 1. プロダクトのコンセプト

**2-Tap HIIT は「メニューを考えるのがめんどくさい人」のための HIIT タイマーアプリ**です。

約束すること:

- ログインなし
- メニュー作りなし
- 細かい設定なし
- 開いて → コースを選んで → セット数を選んで → スタート

フィットネスの総合プラットフォームではありません。
「ジムに行くのも、種目を選ぶのも、細かく記録するのも面倒。でも健康のために少しは体を動かしたい」という人向けの、**手間の少ない小さな宅トレアプリ**です。

---

## 2. リポジトリ構成

```txt
two-tap-hiit/
  native/   # Expo / React Native のモバイルアプリ
  server/   # Cloudflare Workers + Hono + D1 の API（最初は最小限）
  docs/
```

- まずモバイルの MVP を作る
- server は、機能として必要になるまではシンプルな雛形のままにする

---

## 3. 技術スタック

### native（モバイルアプリ）

| 項目 | 内容 |
| --- | --- |
| フレームワーク | React Native + Expo |
| 言語 | TypeScript |
| ルーティング | Expo Router |
| ローカル保存 | 運動した日・広告の表示回数など、小さなデータだけ |
| 多言語対応 | 最初から日本語・英語の2言語 |
| 広告 | AdMob は後で導入。ただし広告を差し込む「フック」は今のうちに用意しておく |

### server

| 項目 | 内容 |
| --- | --- |
| 実行環境 | Cloudflare Workers |
| フレームワーク | Hono |
| DB | D1 |
| 言語 | TypeScript |

ローカルで動く MVP に server は不要です。
将来の **購入レシートの検証・リモート設定・任意の匿名同期** のための雛形として置いておきます。

## 5. 多言語対応

| 言語 | いつ使うか |
| --- | --- |
| 日本語 | 端末の言語が日本語のとき |
| 英語 | それ以外すべて（フォールバック） |

- 画面に出す文言をコンポーネントに直書きしない
- 最初から小さな i18n の仕組みを通して文言を出す

### 文言のトーン

| 英語 | 日本語 |
| --- | --- |
| 率直 | シンプル |
| フレンドリー | カジュアル |
| プレッシャーをかけない | 意識高すぎない |
| アスリートっぽくしすぎない | 「めんどくさくない」を大事に |

## 6. MVP の画面の流れ

```txt
ホーム → コース選択 → セット数選択 → ワークアウト（タイマー） → 完了画面 → ホームに戻る
```

- この流れはできるだけ短く保つ
- OS の権限で必要にならない限り、オンボーディング（使い方説明）は入れない

---

## 7. コース

MVP のコースは **ちょうど2つ** だけです。

| コース | 種目1 | 種目2 | 想定 |
| --- | --- | --- | --- |
| スタンダード（Standard） | バービージャンプ（Burpee） | マウンテンクライマー（Mountain climber） | 定番 |
| 静かめ（Quiet） | ジャンプなしバービー（No-jump burpee） | スクワット（Squat） | マンション住まい・音が気になる人向け |

---

## 8. セット数

選べるのは **2 / 4 / 6 / 8 セット** の4つだけです。

**1セット = 2種目を1回ずつ** です。

```txt
種目A 30秒
休憩  15秒
種目B 30秒
休憩  15秒
```

これを選んだセット数だけ繰り返します。

---

## 9. タイマーのルール

- 運動: **30秒**
- 休憩: **15秒**
- いま「運動中」か「休憩中」かをはっきり見せる
- 休憩中は次の種目を表示する
- 一時停止／再開ができる
- 途中でやめる操作には確認を出す
- 可能な端末では音と振動で合図する
- **ラスト3秒** はカウントダウンの合図をはっきり出す

### 広告を絶対に出さないタイミング

- 運動中
- 休憩中
- 一時停止／再開中
- 開始前のカウントダウン中

## 10. 画面ごとの仕様

### 10.1 ホーム画面

**目的**: すぐにスタートできること。軽く進み具合が見えること（記録アプリっぽくはしない）。

表示するもの:

- アプリ名 `2-Tap HIIT`
- メインのスタートボタン
- 今週の達成ドット（7つの小さな丸。運動した日に色がつく）
- 記録画面へのリンク／ボタン
- （任意）バナー広告の置き場所

> ごちゃごちゃさせない。ホームは「ダッシュボード」ではなく **「スタートボタン」** に見えるように。

### 10.2 コース選択画面

- 「スタンダード」「静かめ」の2つを大きく表示
- それぞれに2つの種目名を載せる
- コース選択 → セット数選択の間に広告は出さない

### 10.3 セット数選択画面

- 2 / 4 / 6 / 8 を表示
- 選んだらすぐワークアウトを始める、または3秒のカウントダウンを挟む
- MVP では、セット数選択 → ワークアウト開始の間に広告は出さない

### 10.4 ワークアウト画面

表示するもの:

- いまのモード（運動 or 休憩）
- いまの種目名
- 残り秒数
- いま何セット目か
- 休憩中は次の種目
- 一時停止ボタン
- 終了ボタン

アニメーション部分:

- 運動アニメーション用のプレースホルダーコンポーネントを置く
- 最初は静止画やシンプルな図形でよい
- 後から Lottie / Rive / GIF / 動画ループに差し替える

### 10.5 完了画面

表示するもの:

- 「おつかれ！」／ "Done"
- コース名
- セット数
- 合計時間
- ホームボタン

広告の動き:

| 状況 | 動き |
| --- | --- |
| 通常 | 完了画面を表示 → **5秒後** に、条件を満たせばインタースティシャル広告を表示 → 閉じたらホームへ |
| 5秒以内にホームボタンを押した | その時点で、条件を満たせば広告を表示 → 閉じたらホームへ |
| 広告が無効・表示できない | 普通にホームへ戻る |

### 10.6 記録画面

記録はシンプルに。

表示するもの:

- カレンダー風のリスト、または月表示
- 運動した日に色をつける
- 今週の回数
- 今月の回数
- （任意）連続日数

MVP では、簡単にできる場合を除き、記録の手動編集は作らない。

広告の動き:

- 将来、ホーム ⇔ 記録の移動でインタースティシャル広告を出すことがある
- 確率は **20〜30%**
- 1日あたり／セッションあたりで回数を制限する
- すばやく行ったり来たりしても、何度も広告が出ないようにする

## 11. ワークアウトの記録

MVP では **端末内（ローカル）にだけ保存** します。

完了した日はローカル日付で保存します。

```ts
type WorkoutDate = string; // YYYY-MM-DD
```

保存するデータの形（案）:

```ts
type WorkoutCompletion = {
  date: string;                   // 完了した日 (YYYY-MM-DD)
  courseId: "standard" | "quiet"; // コース
  setCount: 2 | 4 | 6 | 8;        // セット数
  completedAt: string;            // 完了時刻
};
```

- ログインは必須にしない
- 記録のためにバックエンドを必須にしない

## 12. 広告の方針

最終的には iOS / Android とも Google AdMob を使います。

### 基本の考え方

**広告でワークアウトそのものを邪魔しない。**
このアプリの価値は「手間がかからないこと」なので、スタートまでの導線にも広告は置きません。

### 広告を置いてよい場所／いけない場所

| ✅ 置いてよい | ❌ 置いてはいけない |
| --- | --- |
| ホームのバナー枠 | 運動中 |
| ワークアウト以外の画面のバナー枠 | 休憩中 |
| ワークアウト完了後のインタースティシャル | 一時停止／再開中 |
| ホーム ⇔ 記録の移動時のインタースティシャル（回数制限あり） | コース選択 → セット数選択の間 |
| | セット数選択 → ワークアウト開始の間（MVP） |

### 完了後インタースティシャルのルール

AdMob をつなぐ前から、この状態遷移は実装しておきます。

```txt
ワークアウト完了
→ 完了画面を表示
→ 5秒待つ
→ 条件を満たせばインタースティシャルを表示
→ 閉じたらホームへ
```

5秒経つ前にホームボタンを押した場合:

```txt
ホームボタンを押す
→ 条件を満たせばインタースティシャルを表示
→ 閉じたらホームへ
```

> **1回の完了で出せるインタースティシャルは1回だけ** にすること。

### ホーム ⇔ 記録の移動時の広告ルール

- 確率 20〜30%
- まずは1日1回まで。少なくともクールダウン（一定時間あける）は必須
- 短時間に続けて出さない

保存しておく状態（案）:

```ts
type AdThrottleState = {
  lastInterstitialShownAt?: string; // 最後に広告を出した時刻
  interstitialCountToday: number;   // 今日出した回数
  interstitialCountDate?: string;   // 回数を数えている日
};
```

## 13. 有料の「広告なし」プラン

MVP では無くてもリリースしてよいですが、**後から追加できる設計** にしておきます。

ポイント:

- 広告なしの購入に、ユーザーアカウントや独自 DB は必ずしも必要ない
- 購入状態は App Store / Google Play 側が持っている
- 後から「購入の復元」に対応できるようにしておく

将来 server が担う役割:

- レシートの検証
- リモート設定
- 購入状態の匿名ミラー（任意）
- 不正対策

> 広告なしのためだけに、ログインを必須にしないこと。

## 14. server の MVP

`server/` に Cloudflare Workers + Hono の最小構成を作ります。

最初のエンドポイント:

```txt
GET /health
GET /config
```

`/config` のレスポンス例:

```json
{
  "ads": {
    "recordsTransitionProbability": 0.25,
    "completionInterstitialDelaySeconds": 5
  }
}
```

- native アプリは最初はローカルのデフォルト値で動き、後からサーバーの設定を読むようにする
- D1 のスキーマ設計待ちで native の MVP を止めない

## 15. アニメーションの方針

いきなり複雑な人物アニメーションは作りません。

MVP:

- 再利用できる `ExerciseVisual` コンポーネントを作る
- シンプルなプレースホルダー画像や、アイコン風の動きを表示する
- 本物のアニメーション素材に簡単に差し替えられるようにする

将来の選択肢:

| 方式 | 向いている用途 |
| --- | --- |
| Lottie | 軽いループアニメーション |
| Rive | 状態を持つキャラクターアニメーション |
| 短い動画／GIF ループ | 一番早く用意できる場合 |

> アニメーションの役割は「完璧なフォーム指導」ではなく、**いまの種目が一目でわかること**。

---

## 16. アクセシビリティと UX のメモ

- タイマーの数字は大きく
- コントラストは高く
- ラベルはわかりやすく
- 長い説明を読まなくても使える
- 合図を音だけに頼らない
- 振動を実装するならオフにできるように
- 体育会系の強い言葉を使わない
- ユーザーに罪悪感を持たせない

---

## 17. 実装の順番（推奨）

1. `native/` に TypeScript の Expo アプリを作る
2. ルーティングと多言語対応の土台を入れる
3. コースとタイマーのドメインデータを定義する
4. ホーム画面（今週のドット付き）
5. コース選択画面
6. セット数選択画面
7. ワークアウトタイマー
8. 完了画面とローカルへの記録保存
9. 記録画面
10. モックの広告サービス（ダミー挙動）
11. `server/` に雛形を作る
12. 本物の AdMob を導入（後で）
13. 広告なしの課金を導入（後で）
